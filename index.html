Topic 1 of 5

Number Systems

People count in tens. Computers count in twos. Programmers often write in sixteens. This topic shows why all three exist and how to move between them.

1.1Concept

Why computers use binary

A computer is built from billions of tiny switches called transistors. A switch can only be in one of two states: on or off. That gives a computer exactly two symbols to work with, which we write as 1 (on) and 0 (off). A number system with two symbols is called binary, or base 2. A single binary digit is a bit.

The system you use every day is denary, or base 10. It has ten symbols, 0 to 9, and each column is worth ten times the one to its right: ones, tens, hundreds, thousands. In the number 365, the 3 means three hundreds, the 6 means six tens and the 5 means five ones.

Binary works the same way, except each column is worth two times the one to its right: 1, 2, 4, 8, 16, 32, 64, 128. To read a binary number, add up the place values of every column that holds a 1. Eight bits together make a byte, and four bits make a nibble.

Check your thinking

With all eight bits on you get 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = 255. Counting 0 as well, one byte can store 256 different values.

When counting up, the right-hand bit (worth 1) flips every step and the left-hand bit (worth 128) flips only once. The right-hand bit is called the least significant bit and the left-hand bit is the most significant bit.

256 would need a ninth bit. With only eight bits available the value wraps round to 0. This is called overflow.

1.2Explanation

Converting denary to binary

There are two reliable methods. Both give the same answer, so use whichever you find easier and keep the other for checking.

Subtract place values. Write out the place values 128, 64, 32, 16, 8, 4, 2, 1. Start at the left. If the place value fits into what you have left, write a 1 and subtract it. If it does not fit, write a 0 and move on.

Divide by 2. Keep dividing the number by 2 and write down the remainder each time (it will always be 0 or 1). Stop when you reach 0. The remainders, read from the last one to the first, are the binary number.

1, 2, 4, 8 and 16 each use a single bit. They are the powers of 2, which is why they are the place values.

The right-hand bit is worth 1. Every other place value is even, so a number is odd exactly when that last bit is 1.

1.3Concept

Hexadecimal: binary in shorthand

Long strings of 1s and 0s are hard for people to read and easy to copy wrongly. Hexadecimal, or base 16, solves this. It has sixteen symbols: 0 to 9, then A, B, C, D, E and F for the values 10 to 15.

Sixteen is 2 × 2 × 2 × 2, so one hex digit stands for exactly four bits. A byte splits into two nibbles, and each nibble becomes one hex digit. The byte 1010 0101 becomes A5. Nothing about the data changes. Hex is only a shorter way for humans to write the same bits.

You will meet hex in colour codes on web pages (#FF8800), in the MAC address that identifies a network device (3C:5A:B4:01:9F:E2), in memory addresses and in error codes.

1.4Explanation

Converting between all three

Binary to hex: split the binary number into groups of four bits, starting from the right. Turn each group into one hex digit.

Hex to binary: do the reverse. Replace each hex digit with its four-bit pattern.

Hex to denary: the place values in hex are 1, 16, 256 and so on. For a two-digit hex number, multiply the left digit by 16 and add the right digit. 2F is 2 × 16 + 15 = 47.

Denary to hex: divide by 16. The whole-number answer is the left digit and the remainder is the right digit. 47 ÷ 16 = 2 remainder 15, so the answer is 2F. If you find that hard, go through binary: denary to binary, then binary to hex.

Topic 2 of 5

Data Representation

A computer can only store numbers, and those numbers are in binary. Text, pictures and sound all have to be turned into numbers before a computer can keep them.

2.1Concept

Everything is a number

To store something, a computer needs a rule that turns it into numbers and back again. For text the rule is a character set: a table that gives every character its own number. In the ASCII character set, capital A is 65, capital B is 66 and a space is 32. Each ASCII character fits in one byte.

The more there is to store, the more bits are needed. Storage is measured in these units:

  • 8 bits = 1 byte
  • 1024 bytes = 1 kibibyte (KiB)
  • 1024 KiB = 1 mebibyte (MiB)
  • 1024 MiB = 1 gibibyte (GiB)

In everyday speech people often say kilobyte and megabyte for these sizes. To turn bits into bytes, divide by 8. To turn bytes into KiB, divide by 1024.

Check your thinking

A is 65 and a is 97. They are 32 apart, so only the bit worth 32 changes. Every capital and lower-case pair works this way.

The character 7 has the code 55. A digit typed as text is stored as a character code, which is different from storing the number 7.

2.2Concept

Images are grids of pixels

A digital image is made of tiny squares called pixels. Each pixel is a single colour, and that colour is stored as a binary number. The computer keeps the pixels in order, row by row, so the picture is really one long list of numbers.

The number of bits used for each pixel is the colour depth. With 1 bit a pixel can only be one of 2 colours. With 2 bits there are 4 possible codes (00, 01, 10, 11), so 4 colours. Every extra bit doubles the number of colours: number of colours = 2colour depth.

2.3Explanation
Resolution, colour depth and file size

        

          
Resolution is the number of pixels in an image, given as width × height. More pixels means finer detail, because each pixel covers a smaller part of the picture. Too few pixels and you can see the squares. The image looks blocky, or pixelated.

          
Colour depth controls how accurate each pixel's colour is. Photographs normally use 24 bits per pixel, which gives over 16 million colours. With a low colour depth, smooth shading turns into flat bands because there are not enough colours to go round.

          
Both settings improve quality and both make the file bigger:

          
file size in bits = width × height × colour depth

          
Real image files also hold a little extra information called metadata, such as the width, height and colour depth, so the computer knows how to rebuild the picture.

2.4Concept
Sound is measured thousands of times a second

        

          
Sound travels as a smooth, continuously changing wave. That kind of signal is called analogue. A computer cannot store a smooth curve, so it measures the height of the wave at regular moments and stores each measurement as a binary number. Each measurement is a sample.

          
The sampling rate is the number of samples taken each second, measured in hertz (Hz). A higher rate catches quick changes in the wave that a lower rate would miss. Music on a CD uses 44,100 samples per second.

          
The bit depth (also called sample resolution) is the number of bits used to store each sample. With 3 bits there are only 8 possible heights, so every measurement gets rounded to the nearest one. With 16 bits there are 65,536 heights and the rounding is too small to hear.

          
file size in bits = sampling rate × bit depth × seconds × channels

          
Mono sound has one channel. Stereo has two, one for each ear, so it takes twice the space.

Topic 3 of 5

    
Error Checking

    
Data gets damaged on its way between computers. The receiver cannot see what the sender meant, so the sender adds a little extra information that lets the receiver test whether the data arrived intact.

  

  

    

    


      

        
3.1Concept
How errors happen

        

          
Data travels as electrical pulses in a cable, flashes of light in a fibre or radio waves through the air. Along the way the signal can be disturbed by interference: other electrical equipment, a weak Wi-Fi signal, a damaged cable. When the disturbance is strong enough, a 1 is read as a 0 or a 0 is read as a 1. One flipped bit is enough to turn one letter into another.

          
The receiver has a problem. Damaged data looks just as valid as good data. To find errors, the sender and receiver have to agree on a check in advance.

Errors are random, so each send is damaged differently and some arrive perfect. This is why sending the data again is a good fix once an error has been noticed.

            
One flipped bit changes the character code by 1, 2, 4, 8, 16, 32 or 64, which gives a completely different character.

          

        

      


      

        
3.2Explanation
Parity check

        

          
A parity check adds one extra bit, the parity bit, to every byte. Seven bits carry the data and the eighth is set so that the total number of 1s follows a rule the two computers agreed on.

          
    
            
  • Even parity: the byte must contain an even number of 1s.
    • 
            
  • Odd parity: the byte must contain an odd number of 1s.
    • 
          

          
The sender counts the 1s in the data and sets the parity bit to make the total fit the rule. The receiver counts the 1s in the byte that arrives. If the count breaks the rule, a bit must have flipped on the way, and the receiver asks for the byte again.

          
Parity has two limits. It cannot tell you which bit is wrong. And if two bits flip, the count goes back to fitting the rule, so the error is missed.

A parity block improves on this. The bytes are stacked in rows, each with its own parity bit, and one extra row called the parity byte holds a parity bit for every column. A single flipped bit now breaks the rule in one row and in one column. Where they cross is the faulty bit, so the receiver can correct it without asking for the data again.

3.3Explanation
Checksum

        

          
A checksum checks a whole block of data at once. Before sending, the sender runs a calculation on all the bytes in the block and sends the answer along with the data. The receiver runs the same calculation on what arrived and compares its answer with the checksum that was sent. If the two differ, the block is damaged and the receiver asks for it again.

          
A simple checksum, used below, is to add up all the bytes and keep only the remainder after dividing by 256, so the result fits in one byte. Real networks use more complicated calculations that catch more kinds of error, but the idea is the same.

3.4Explanation
Check digit

        

          
The first two methods catch errors made by cables and radio waves. A check digit catches errors made by people and scanners when a number is entered: a mistyped digit, or two digits swapped round.

          
A check digit is one extra digit on the end of a code, calculated from all the other digits. You will find one on every barcode, on bank card numbers and on the ISBN printed on the back of a book. When the code is typed or scanned, the computer redoes the calculation. If the answer does not match the last digit, the code is rejected straight away.

          
For a 13-digit ISBN the calculation is: multiply the first twelve digits by 1, 3, 1, 3 and so on in turn. Add up the results. The check digit is the number you must add to reach the next multiple of 10.

Two more methods to know

          
Echo check: the receiver sends the data straight back and the sender compares it with the original. If the two differ, the data is sent again.

          
Automatic repeat request (ARQ): the receiver replies with an acknowledgement when data passes its error check. If the sender gets no acknowledgement within a set time, it sends the data again automatically.

Logic Gates

    
Every decision a computer makes comes down to a handful of simple rules applied to 1s and 0s. Each rule is carried out by a small circuit called a logic gate.

  

  

    

    


      

        
4.1Concept
What a logic gate does

        

          
A logic gate is a tiny electronic circuit made from transistors. It takes one or two binary inputs and produces one binary output. The output depends only on the inputs and on the gate's rule. The same inputs always give the same output.

          
In a real circuit, 1 means a wire is carrying a voltage and 0 means it is not. You can also read 1 as true and 0 as false. That lets a gate answer questions like "are both of these true?" or "is at least one of these true?".

4.2Explanation
Truth tables

        

          
A truth table lists every possible combination of inputs and the output each one gives. It is a complete description of a gate or a circuit: if two circuits have the same truth table, they behave identically.

          
The number of rows depends on the number of inputs. Each input can be 0 or 1, so one input needs 2 rows, two inputs need 4 rows and three inputs need 8 rows. In general, rows = 2number of inputs.

          
To make sure no combination is missed, write the inputs in binary counting order: 00, 01, 10, 11. For three inputs count from 000 up to 111.

4.3Explanation
Logic circuits

        

          
One gate cannot do much. Useful behaviour comes from joining gates together so that the output of one becomes the input of another. This is a logic circuit.

          
To work out what a circuit does, go from left to right. Find the output of the first gate, write it on the wire, then use it as an input for the next gate. Carry on until you reach the final output. In a truth table for a circuit, it helps to add a column for each of these in-between wires.

          
A circuit can also be written as a logic expression. Brackets show which part is worked out first, just as in maths. X = A AND (B OR C) means "work out B OR C, then AND the result with A".

Topic 5 of 5

    
Computer Architecture

    
A program is a list of very small instructions. The processor carries them out one at a time, billions of times a second, by repeating the same three stages over and over.

  

  

    

    


      

        
5.1Concept
The stored program computer

        

          
Almost every computer you use follows a design described by John von Neumann in 1945. Its key idea is the stored program concept: the instructions of a program are kept in the same memory as the data they work on, and both are stored as binary numbers.

          
The design has two main parts. The central processing unit (CPU) carries out instructions. Memory (RAM) holds the instructions and data the CPU is using right now. Memory is a long row of storage locations. Each location has an address, which is its position number, and contents, which is the binary value stored there.

          
The CPU and memory are joined by sets of wires called buses. The address bus carries the address the CPU wants to use. The data bus carries the value being moved. The control bus carries signals such as "read" and "write".

        

      


      

        
5.2Explanation
Inside the CPU

        

          
The CPU has three kinds of component. The control unit (CU) is the manager. It works out what each instruction means and sends signals telling the other parts what to do. The arithmetic logic unit (ALU) does the calculations and comparisons. It is built from logic gates like the ones in Topic 4.

          
Registers are very small, very fast stores inside the CPU. Each holds one value and has one job. Five of them matter here: the PC, MAR, MDR, CIR and ACC.

5.3Explanation
The fetch–decode–execute cycle

        

          
The CPU handles every instruction in the same three stages.

          
    
            
  1. Fetch. The address in the PC is copied to the MAR. The instruction stored at that address travels along the data bus into the MDR, then is copied into the CIR. The PC goes up by 1 so that it points at the next instruction.
    2. 
            
  2. Decode. The control unit splits the instruction in the CIR into two parts. The opcode says what to do. The operand says which memory address to do it with.
    3. 
            
  3. Execute. The instruction is carried out. That might mean loading a value from memory, doing a calculation in the ALU, storing a result or jumping to a different instruction.
    4. 
          

          
Then the cycle starts again with the next instruction. A CPU with a clock speed of 3 GHz runs about three billion of these cycles each second.

The PC, MAR, MDR and CIR change during every fetch. The fetch stage is identical for every instruction. Only the execute stage differs.

            
A jump or branch instruction writes a new address into the PC. That is how a program repeats a section of code (a loop) or chooses between two paths.

            
The accumulator holds 8 bits, so its largest value is 255. 300 does not fit, and the result wraps round to 300 − 256 = 44. This is overflow, the same effect you saw in Topic 1.
